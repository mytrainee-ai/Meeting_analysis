# План развития

Текущий статус: MVP реализован и опубликован на пилотном сервере. Последние требования фиксируются в [PRD](03-prd.md), решения — в [DECISIONS.md](DECISIONS.md), подробное состояние и эксплуатационные ограничения — в [CURRENT_STATE.md](CURRENT_STATE.md) и [DEPLOYMENT.md](DEPLOYMENT.md).

## Реализовано

### Приложение

- Вход, первоначальная настройка администратора, регистрация по приглашениям и серверные проверки ролей/владельца.
- Страница встреч со сводными счётчиками, статусом обработки и результатами; карточка встречи с редактированием полей и результатов.
- Загрузка MP4/WebM до 25 МБ/10 минут с фактическим прогрессом, активным индикатором ожидания, отменой и согласием на облачную обработку.
- Автоматическая фоновая обработка; расшифровка фактической речи и структурированные итоги с цитатной проверкой.
- Повтор неуспешной обработки; просмотр безопасной диагностики AI API и FFmpeg.
- Массовое удаление только встреч текущего пользователя. Учётные записи и приглашения сохраняются; при активной обработке удаление блокируется.
- Истечение видео и временного аудио через 24 часа; текстовые результаты сохраняются до удаления встречи.
- Сессионная cookie входа, которая завершается при закрытии браузера и отзывается при старте приложения.

### Серверный пилот

- Пилот опубликован по HTTPS на `app.traineeserver.ru`; домен, Nginx/Certbot, UFW и systemd настроены.
- Одна Ubuntu VM, Python 3.12, FFmpeg/FFprobe, один Uvicorn worker, SQLite и локальное постоянное хранилище.
- GitHub Actions автоматически публикует push в `main`; repository variable `PILOT_DEPLOY_ENABLED` включена. Workflow проверяет `/health` и может откатить релиз.
- Серверная база создавалась пустой; локальные аккаунты и встречи не переносились.

## Ограничения текущего пилота

- Фоновые задачи работают внутри процесса приложения. Перезапуск во время обработки может прервать задачу; её запускают повторно вручную.
- Приложение рассчитано на один worker и одну VM; очередь задач и объектное хранилище не подключены.
- Резервное копирование отложено решением владельца пилота.
- Последние изменения интерфейса и сессий считаются опубликованными только после успешного workflow в GitHub Actions.
