# Текущее состояние

Дата обновления: 2026-11-06

## Готово

- Прочитаны документы определения продукта, технического исследования и PRD.
- Согласован предварительный дизайн трёх экранов: обзор, отдельная встреча, загрузка/обработка.
- На экранах без содержимого используются пустые состояния; демонстрационные данные запрещены.
- Пользователь видит и изменяет только загруженные им встречи; администратор видит все встречи. Сервер проверяет владельца при чтении и запуске обработки.
- Загрузка должна показывать реальный прогресс и ошибки; по завершении есть кнопка «Открыть встречу».
- Внешние ссылки для загрузки отложены, но учтены как будущее расширение.
- Уточнено: последовательные AI-правки отложены, но должны учитываться на будущее.
- Создан проект на Python 3.12 с виртуальным окружением `.venv`.
- Создано минимальное приложение FastAPI с `/health`.
- Инициализирован локальный Git на `main`; настроен `origin`.
- Добавлен `.env.example`. Локальный `.env` исключён из Git.
- Созданы документы архитектуры, решений, плана и текущего состояния.
- Добавлен локальный экран загрузки MP4/WebM с реальным прогрессом передачи, перетаскиванием, отменой передачи и явным возвратом к списку встреч.
- Сервер ограничивает размер multipart-запроса и файла 25 МБ; FFprobe определяет MP4/WebM по содержимому, проверяет видеодорожку, длительность до 10 минут и аудиодорожку, а FFmpeg декодирует первые видеодорожку и аудиодорожку.
- Валидный MP4/WebM сохраняется в `data/uploads` с расширением, определённым по фактическому контейнеру, метаданные и статус `uploaded` — в SQLite. После загрузки доступна страница встречи; статус сохраняется при обновлении.
- Добавлена понятная обработка ошибок формата, размера, длительности, отсутствующей аудиодорожки и недоступного FFprobe.
- Добавлена зависимость `python-multipart`; каталог `data/` исключён из Git. Путь данных задаётся через `MEETING_DATA_DIR`.
- Для этапа обработки добавлены отдельный явный запуск из карточки встречи, предупреждение о передаче аудио/текста в OpenAI API и расходах, сохраняемые статусы, ручной повтор и вывод пяти секций с цитатами.
- Добавлены локальные зависимости OpenAI Python SDK и `python-dotenv`. Транскрипт записывается до AI-анализа; повтор после ошибки анализа использует сохранённую расшифровку.
- Для обработки видео использован уже загруженный пользователем MP4; файл не копировался и не заменялся демонстрационными данными.
- Реальная встреча обработана: получена расшифровка, сформированы темы, решение и краткое содержание; результаты сохранены у исходной встречи.
- Добавлены главная страница со списком встреч и ссылка на загрузку.
- Добавлены локальная первоначальная настройка администратора, вход/выход, 12-часовая подписанная сессия и регистрация по активному приглашению; пароль при настройке/регистрации — минимум 8 символов.
- Добавлены серверные проверки роли для управления приглашениями, пользователями и удаления встреч; анонимные запросы отклоняются до разбора multipart-тела. Для каждой встречи записывается владелец; обычные пользователи ограничены собственными встречами, администратор видит все.
- Добавлены выпуск/отзыв многоразовых кодов приглашений, блокировка и разблокировка обычных учётных записей.
- Добавлена очистка видео через 24 часа при старте и успешном просмотре списка/карточки; транскрипт и итоги сохраняются. Временные аудио удаляются после обработки и очищаются по сроку.
- Администратор может удалить встречу вместе с локальным видео и текстовыми результатами; при неудаче физического удаления запись сохраняется.

## Проверено

- Приложение импортируется в виртуальном окружении Python 3.12.
- Функция маршрута `/health` возвращает `{"status": "ok"}`.
- `.venv` и `.env` исключены из Git.
- В среде разработки доступны Python 3.12, `ffprobe` и `ffmpeg`; в `.venv` установлен `python-multipart`.
- Подтверждена загрузка пользовательского MP4 16,5 МБ и длительностью 386 секунд; файл хранится в `data/uploads`, API и страница встречи отвечают 200.
- Полный поток AI-обработки завершён со статусом `completed`; расшифровка 4221 символ, сводка 2 пункта, темы 3, решение 1; задач и открытых вопросов по цитируемой расшифровке не выявлено.
- Проверены все 6 цитат результата — каждая дословно присутствует в расшифровке. Страница встречи/API отвечают 200, временных аудиофайлов после завершения не осталось.
- Новые модули компилируются; проверено, что правильный пароль проходит проверку, а неверный отклоняется.
- После перезапуска `/health` и `/setup` отвечают 200; экран настройки содержит поля почты/пароля, а анонимные запросы списка, карточки и upload API отклоняются с 401.
- Cross-site POST на первоначальную настройку отклоняется с 403.
- Миграция добавила `owner_id`; существующая встреча и её статус/расшифровка сохранены, запись без владельца видна только администратору.
- Проверка API с реальными ролями: администратор получил старую встречу (200), обычный пользователь получил пустой список и 404 на прямое чтение.
- `/health` отвечает 200, Python-модули компилируются, `git diff --check` не выявил ошибок форматирования.
