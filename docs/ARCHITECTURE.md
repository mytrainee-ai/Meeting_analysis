# Архитектура

## Назначение

Веб-приложение принимает видеозаписи встреч, получает расшифровку реальной речи через внешний AI-сервис и показывает расшифровку и структурированные итоги. Подробные требования приведены в [PRD](03-prd.md).

## Архитектурное направление

- Серверная часть: Python 3.12, FastAPI.
- Вызовы облачного API выполняются только сервером; ключи не попадают в браузер.
- `OPENAI_BASE_URL` задаёт OpenAI-совместимый endpoint; по умолчанию используется OpenAI. ProxyAPI рассматривается как настраиваемая альтернатива после проверки совместимости.
- Видео проверяется по фактическому содержимому, контейнеру, длительности и наличию аудио. Для анализа медиа предусмотрен FFmpeg/FFprobe.
- Тяжёлая обработка не должна блокировать HTTP-запрос. Для неё нужны сохраняемые статусы и фоновое выполнение; конкретная очередь будет выбрана при реализации обработки.
- Метаданные и результаты хранятся отдельно от бинарных медиафайлов. Локально допустима файловая система; для развёртывания рассматриваются реляционная БД и приватное объектное хранилище.
- Архитектура должна допускать увеличение лимита и потоковую загрузку в будущем, но MVP принимает видео до 25 МБ и 10 минут.

## Доступ и данные

- Первая версия имеет роли администратора и студента. Студент регистрируется по активному приглашению; публичной регистрации нет.
- Обычный пользователь видит и обрабатывает только свои встречи; администратор видит все встречи и может их удалять.
- Видео и временное аудио удаляются через 24 часа после загрузки. Расшифровка и текстовые результаты хранятся до удаления встречи администратором.
- Встречи и медиа доступны только после входа; постоянные публичные ссылки на файлы запрещены.

## Поток обработки

1. Сервер принимает загрузку и проверяет ограничения до платного вызова AI.
2. FFprobe проверяет медиа, FFmpeg извлекает и при необходимости сжимает аудио.
3. Внешний сервис транскрибирует русскую речь.
4. AI анализирует транскрипт и формирует краткое содержание, темы, решения, задачи и открытые вопросы.
5. Статусы и результаты сохраняются так, чтобы обновление страницы не запускало повторную обработку.

Имена ответственных, решения и сроки нельзя додумывать. Если расшифровка их не подтверждает, поля остаются пустыми или явно помечаются как неопределённые.

## Текущая реализация

- FastAPI обслуживает страницу загрузки и API загрузки MP4/WebM. Браузер использует `XMLHttpRequest.upload.onprogress`, поэтому отображается фактический ход передачи, а не имитация.
- Загрузка ограничена на уровне ASGI-запроса и по фактическому размеру файла. FFprobe определяет MP4/WebM по содержимому, проверяет видеодорожку, длительность до 600 секунд и наличие аудиодорожки; FFmpeg декодирует первые видеодорожку и аудиодорожку. Неподдерживаемый или повреждённый файл не создаёт встречу.
- Видео MP4/WebM хранится в `data/uploads` с определённым по содержимому расширением; метаданные (включая расширение) и статус — в SQLite `data/meetings.sqlite3`. `MEETING_DATA_DIR` позволяет изменить корневой каталог хранения.
- Загрузку можно отменить и вернуться к списку. После обязательного согласия файл получает статус `processing_audio_extraction`, обработка запускается автоматически, а браузер возвращается к списку встреч.
- Авторизационная cookie действует только в сессии браузера (без `Max-Age`). Ключ подписи выводится из постоянного `APP_SECRET_KEY` с новым случайным nonce при каждом старте процесса, поэтому перезапуск сервера отзывает старые сессии. При пустом `APP_SECRET_KEY` приложение генерирует его и сохраняет только в `.env`; для HTTPS нужно выставить `COOKIE_SECURE=true`.
- Первый администратор создаётся в локальном мастере первоначальной настройки; этот маршрут доступен только с loopback. Регистрация остальных аккаунтов требует активный многоразовый код приглашения; в БД хранится только хеш кода. Администратор может отзывать коды и блокировать обычные учётные записи.
- Auth middleware отклоняет анонимные запросы до разбора защищённых запросов, включая multipart-загрузку. API повторно проверяют вход и роль; удаление встречи и администрирование требуют роль `admin`.
- Главная страница показывает сохранённые встречи. Записи фильтруются на сервере по owner_id; чтение и запуск обработки повторно проверяют владельца. Администратор может обращаться ко всем встречам. Старые записи без владельца видны только администратору.
- Сводная панель запрашивает `/api/meetings/summary`; сервер считает обработанные встречи, решения, задачи, открытые вопросы и неуспешные статусы в той же области доступа, что и список. Интерфейс не подставляет демонстрационные значения.
- Строки списка показывают название, дату/время, тему из первого результата либо повестки, статус, длительность и счётчики результатов. Фото и число участников не используются; колонка «…» — неактивный placeholder.
- Upload API требует согласие на облачную обработку. Браузер начинает передачу сразу после выбора файла и наличия согласия; отдельной кнопки отправки нет. После сохранения записи API планирует `process_meeting` как фоновую задачу и возвращает статус `processing_audio_extraction`. Страница загрузки затем переводит пользователя к списку; список опрашивает статусы, пока обработка не завершится.
- Очистка по сроку запускается при старте и при успешных запросах списка/карточки/повторной обработки. После 24 часов удаляется исходное видео; transcript и итоги остаются. Незавершённая очистка при ошибке файловой системы повторяется при следующей проверке.
- Администраторское удаление сначала физически удаляет видео и временные материалы, затем удаляет запись и текстовые результаты из SQLite; если физическая очистка завершается ошибкой, запись остаётся и API возвращает ошибку.
- Для загрузки установлен пакет `python-multipart`; `ffprobe` и `ffmpeg` должны быть доступны через `PATH`.
- Обработка запускается отдельным явным POST-действием с предупреждением в интерфейсе о передаче аудио и транскрипта в облако и возможной оплате по тарифу API. Статусы и транскрипт сохраняются в SQLite; для локального этапа используется фоновая задача FastAPI, незавершённая задача после перезапуска помечается как неуспешная.
- Перед транскрибацией FFmpeg формирует моно MP3 24 кГц/64 кбит/с во временном каталоге; размер проверяется до отправки, временный каталог удаляется после запроса. Расшифровка сохраняется до отдельного вызова структурированного анализа.
- Анализ использует `OPENAI_MODEL` (по умолчанию `gpt-6-luna`) и JSON Schema. Пункты с цитатами, которые не находятся в расшифровке дословно, отбрасываются.
- Карточка встречи позволяет редактировать название/дату, повестку, заметки, следующую встречу, расшифровку и все группы структурированных результатов. `PUT /api/meetings/{id}` проверяет владельца на сервере, ограничивает длину полей и запрещает сохранение во время обработки.
