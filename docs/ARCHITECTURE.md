# Архитектура

## Назначение

Приложение на FastAPI принимает записи встреч MP4/WebM, извлекает аудио, получает расшифровку реальной русской речи через AI API и показывает пользователю текст и подтверждённые расшифровкой результаты. Актуальные требования продукта — в [PRD](03-prd.md), текущие решения — в [DECISIONS.md](DECISIONS.md).

## Компоненты и хранение

- Python 3.12, FastAPI, один Uvicorn worker.
- OpenAI Python SDK. `OPENAI_BASE_URL` задаёт endpoint (по умолчанию OpenAI); `OPENAI_API_KEY`, модели и другие секреты находятся только в локальном `.env` или серверном `/etc/meeting-analysis/.env`.
- FFprobe проверяет контейнер, дорожки и длительность; FFmpeg декодирует и формирует моно MP3 24 кГц/64 кбит/с для транскрибации.
- SQLite хранит аккаунты, приглашения, владельцев встреч, статусы, расшифровки и результаты. Видео хранится отдельно от базы; `MEETING_DATA_DIR` задаёт каталог данных.
- Локально по умолчанию данные находятся в `data/`; на пилотном сервере — в `/var/lib/meeting-analysis`.

## Доступ и сессии

- Роли: `admin` и `user`. Регистрация требует активного приглашения и имени; публичной регистрации нет.
- Список и API проверяют владельца на сервере. Пользователь видит и меняет только свои встречи; администратор видит все встречи и управляет приглашениями/доступом.
- Пользователь может удалить свои встречи через массовое действие. Сервер удаляет только строки с `owner_id` текущего аккаунта и связанные медиа; аккаунты и приглашения не затрагиваются. Администратор может удалить отдельную встречу. Массовое удаление отклоняется, если у владельца есть активная обработка.
- Авторизационная cookie действует в пределах браузерной сессии. Ключ подписи выводится из постоянного `APP_SECRET_KEY` с новым случайным nonce при каждом старте приложения, отзывая старые cookies после перезапуска. Для HTTPS используется `COOKIE_SECURE=true`.
- Файлы и защищённые API требуют входа; сервер повторно проверяет роль/владельца, независимо от интерфейса.

## Загрузка и обработка

1. Пользователь выбирает MP4/WebM до 25 МБ и 10 минут, подтверждает передачу в облако и возможные расходы.
2. Сервер проверяет фактическое содержимое, длительность, наличие и декодируемость аудио/видео до AI-запроса.
3. `XMLHttpRequest.upload.onprogress` показывает фактический ход передачи. Вращающийся индикатор остаётся видимым до ответа сервера, даже при 100%; загрузку можно отменить.
4. После принятия файла приложение запускает `process_meeting` как FastAPI background task и возвращает пользователя к списку. Список опрашивает статус обработки.
5. FFmpeg извлекает временный MP3. Транскрипция выполняется моделью из `OPENAI_TRANSCRIPTION_MODEL` (по умолчанию `gpt-transcribe`) без параметра `languages`, так как настроенная модель его не поддерживает.
6. AI-анализ формирует структурированный JSON по схеме. Неподтверждённые дословными цитатами пункты отбрасываются. Повтор обработки использует уже сохранённую расшифровку, если она есть.
7. Ошибки сохраняют безопасную диагностику конкретной встречи: этап, тип, время, HTTP-код/request ID AI-провайдера или код завершения/последние строки stderr FFmpeg. Диагностика доступна только владельцу и администратору; ключи не возвращаются.

## Хранение и эксплуатационные ограничения

- Видео и временное аудио очищаются по политике 24 часов; расшифровки и текстовые результаты остаются до удаления встречи.
- Фоновые задачи выполняются внутри одного веб-процесса. Перезапуск во время обработки может прервать её; встречу запускают повторно вручную. Несколько workers/реплик не поддерживаются текущей схемой.
- Серверный пилот работает на одной VM с SQLite и постоянным локальным диском. Внешняя очередь и объектное хранилище не используются.
- Резервные копии пилота отложены отдельным решением владельца; см. [DEPLOYMENT.md](DEPLOYMENT.md).
