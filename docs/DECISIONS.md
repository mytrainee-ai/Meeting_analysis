# Принятые решения

## Продукт

1. Сервис анализирует фактическую речь из загруженного видео; демонстрационные данные не заменяют обработку записи.
2. Язык распознавания первой версии — русский.
3. Первая учебная версия рассчитана на администратора и обычных пользователей; отдельная роль проверяющего не используется.
4. Регистрация доступна по активному многоразовому коду приглашения; публичной регистрации нет.
5. Пользователь видит и меняет только загруженные им встречи и результаты обработки. Администратор видит и меняет все встречи, а также управляет приглашениями, доступом и настройками программы и может удалять встречи. Старые встречи без установленного владельца доступны только администратору.
6. Передача аудио внешнему облачному AI разрешена. До первой отправки интерфейс должен сообщить администратору о передаче.
7. Исходное видео и временное аудио хранятся не более 24 часов; расшифровка и результаты — до удаления встречи администратором.
8. Разделение по говорящим и определение личности по голосу не входят в первую версию.
9. Последовательные AI-правки не обязательны для первой версии. Их следует учитывать при проектировании хранения и результатов; добавление планируется на будущее с предпросмотром и явным подтверждением пользователя.
10. Лимиты первой версии: MP4/WebM, не более 25 МБ и 10 минут.
11. Выбор файла начинает передачу автоматически после явного согласия на облачную обработку и возможные расходы; отдельной кнопки отправки нет. После приёма файла обработка запускается автоматически, а интерфейс возвращает пользователя к списку встреч; повтор после ошибки остаётся явным действием.
12. После завершения анализа поля повестки, выводов и следующей встречи автоматически заполняются только сведениями, подтверждёнными точными цитатами из расшифровки. Дата встречи изначально устанавливается по дате загрузки; все поля остаются доступными для ручной корректировки.
13. Регистрация запрашивает имя и сохраняет его в учётной записи. В списке всех встреч, доступном администратору, отображается имя загрузившего (владельца) встречи; API обычного пользователя имя владельца не раскрывает. Для старых аккаунтов без имени используется почта как резервная подпись.
14. Диагностика ошибки обработки хранится отдельно для встречи и доступна в интерфейсе только её владельцу и администратору. Она содержит безопасные метаданные ошибки и очищенное сообщение API; системные журналы и секреты пользователям не выдаются.
15. Пользователь может массово удалить только встречи, принадлежащие его учётной записи. Учётные записи, приглашения и регистрации при этом не меняются. Массовое удаление целиком отклоняется, пока хотя бы одна его встреча обрабатывается; администратор сохраняет возможность удалять отдельные встречи.

## Технологии и окружение

1. Локальная разработка ведётся на Python 3.12 в `.venv`.
2. Для серверного API выбран FastAPI.
3. Репозиторий Git использует ветку `main`; `origin` настроен на `git@github.com:mytrainee-ai/Meeting_analysis.git`.
4. Базовый адрес AI API настраивается через `OPENAI_BASE_URL`; начальное значение — `https://api.openai.com/v1`. Совместимость альтернативного endpoint проверяется отдельно.
5. `.env` содержит локальные секреты и не добавляется в Git. В репозитории хранится только пример `.env.example`.
6. Первого администратора создают один раз через локальную страницу настройки; этот маршрут доступен только с loopback. Пароль должен содержать не менее 8 символов и хранится как scrypt-хеш.
7. Срок сессии локального MVP — 12 часов. Cookie подписана `APP_SECRET_KEY`, имеет HttpOnly и SameSite=Lax; для HTTPS выставляется `COOKIE_SECURE=true`.
8. Код приглашения многоразовый до отзыва; в БД хранится SHA-256-хеш, исходный код показывается администратору только при создании.

## Открытые решения

- Конфигурация и регион следующего сервера после ограниченного пилота.
- Нужны ли после пилота PostgreSQL, устойчивая очередь фоновых задач и объектное хранилище вместо SQLite, in-process обработки и локального диска.
- Точный идентификатор поддерживаемой модели у выбранного AI endpoint и оценка расходов.
- Сброс пароля и управление им после первоначальной настройки.
- Точный текст уведомления о внешней обработке и требования к браузерам.

## Серверный пилот

1. Целевая среда — предоставленная владельцем VM Ubuntu 26.04.1 LTS (1 vCPU, 2 ГБ RAM, 20 ГБ NVMe).
2. Для ограниченного пилота использовать один Uvicorn worker, SQLite и постоянный локальный каталог данных. Не запускать реплики приложения и не размещать PostgreSQL/Redis на этой VM.
3. Перезапуск активной AI-обработки может прервать in-process задачу; встречу можно обработать повторно вручную. Переход на устойчивую очередь и внешние хранилища отложен до оценки потребности/ресурсов.
4. Эти решения относятся только к пилотной серверной конфигурации и не меняют продуктовые сроки хранения, требования доступа или лимиты загрузки.
5. Первый серверный запуск использует новую пустую SQLite-базу. Локальные пользователи, приглашения, встречи, транскрипты и медиа на сервер не переносятся.
6. Обновление пилотного сервера автоматизируется через GitHub Actions при push в `main`. GitHub отправляет только архив отслеживаемого кода; `.env` и `data/` исключаются, OpenAI API key хранится только на сервере.
7. Для учебного пилота резервное копирование не настраивается. Владелец принимает риск потери данных при сбое или удалении VM; решение пересмотреть перед хранением важных пользовательских встреч.

## Дизайн учебной версии

1. Предусмотрены три экрана: обзор, встреча, загрузка/обработка.
2. На обзоре и в карточке встречи показываются пустые состояния, без демонстрационных встреч и результатов.
3. Этап загрузки поддерживает MP4 и WebM, показывает фактический прогресс и ошибки, позволяет отменить активную передачу и вернуться к списку встреч. После успешной загрузки показывается кнопка «Открыть встречу».
4. Загрузка по внешней ссылке отложена; возможность добавления ссылок (например, Google Drive/Dropbox) учитывается как будущее расширение.
5. Панель на странице «Встречи» показывает только вычисляемые по реальным доступным встречам показатели: обработанные встречи, решения, задачи, открытые вопросы и ошибки. Демо-цифры и фиктивные тренды запрещены.
6. Строка встречи не показывает количество участников и фото. Меню «…» пока остаётся заглушкой.
