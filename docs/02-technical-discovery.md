# Этап 2. Technical Discovery

**Статус:** исследование вариантов; решения MVP предварительные  
**Дата:** 2026-11-06  
**Основа:** утверждённое описание продукта в `01-product-definition.md`  
**Проверено по официальным источникам:** OpenAI API docs, официальные репозитории GitHub, FastAPI, PostgreSQL, FFmpeg и MinIO.

> **Исторический обзор вариантов на 2026-11-06.** Рекомендации по PostgreSQL/S3/очередям, развёртыванию и пользовательским ролям не всегда совпадают с реализованным учебным пилотом. Текущая схема — одна VM, один Uvicorn worker, SQLite и локальный диск; актуальные продуктовые требования находятся в [03-prd.md](03-prd.md), принятые решения — в [DECISIONS.md](DECISIONS.md), эксплуатационное состояние — в [DEPLOYMENT.md](DEPLOYMENT.md).

## Краткий вывод

Для первого этапа: облачное распознавание и анализ через OpenAI-совместимый API, начальный `OPENAI_BASE_URL=https://api.openai.com/v1` и переключение на `https://api.proxyapi.ru/v1`, видео до 25 МБ и 10 минут, без обязательных меток говорящих. Разделить задачи обработки и хранение по типу данных. Хотя пользовательский лимит видео на первом этапе равен 25 МБ, архитектуру загрузки и очереди следует спроектировать так, чтобы позднее можно было поддержать потоковую загрузку/чанкинг для больших файлов без смены модели данных. Требование 25 МБ относится к исходному файлу продукта; API транскрибации также имеет лимит 25 МБ на аудио, поэтому извлечённую дорожку нужно кодировать с контролем размера.

Пользователь подтвердил: редактирование изображений в продукт не входит. Исследование API и demo репозитория сохранено как выполненная отдельная ветка задания, но эти компоненты не входят в архитектуру продукта. Администратор меняет только текстовые выводы встречи.

## 1. Редактирование изображений по исходнику и последовательные правки

### Варианты OpenAI

**Статус по решению интервью:** эта функция не входит в продукт. Сравнение ниже документирует исследование, но не является рекомендацией к интеграции.

| Вариант | Для чего подходит | Качество и управление | Цена и задержка | Интеграция и ограничения |
|---|---|---|---|---|
| **Responses API + image generation tool** (`gpt-image-2.5-sunburst` / `...-flare`) | Диалоговый редактор: «измени фон», затем «верни предмет», затем ещё уточнения | Контекст диалога и ссылки на прошлые response/image IDs поддерживают многошаговое редактирование. Sunburst позиционируется для точных правок; Flare — для быстрых качественных итераций. Маска направляет редактирование, но границы не гарантированно соблюдаются пиксельно | Цена зависит от текстовых и image input/output tokens; низкий/средний/высокий output quality для GPT Image 2.5 ориентировочно $0.009/$0.034/$0.133 за квадрат 1024×1024, плюс input tokens. Фиксированной задержки/ SLA в исследованных материалах нет; streaming даёт промежуточные изображения | Лучший fit для интерактивных серий правок. Хранить собственный master-оригинал и версии, не полагаться только на контекст провайдера. Для каждой версии явно сохранять промпт, image ID/байты и родителя |
| **Images API `/v1/images/edits`** | Одна изолированная правка изображения или правка по маске/markup | Принимает до 16 reference images; можно направить edit прозрачной маской или разметкой. Документация предупреждает, что маска — подсказка, не точный pixel mask | Тот же модельный тариф; прямой запрос без цепочки conversation проще оценивать. Потоковая выдача доступна | Хорош для одношагового edit. Для цепочки приложение само передаёт предыдущий output как следующий input и ведёт историю версий |
| **Локальные редакторы на базе ComfyUI / diffusion** | Требования к локальному контролю, приватности, повторяемому графу обработки | Нет одного качества: зависит от checkpoint, workflow, ControlNet/inpainting и GPU; нужна собственная оценка на конкретных материалах | Нет тарифа за запрос, но нужны GPU, электричество, хранение и обслуживание. Задержка сильно зависит от GPU и конфигурации | Больше настройки, конфликтующих лицензий моделей и сопровождения. Продуктовое описание не требует локальной генерации, поэтому сейчас не выбирать без подтверждённой причины |

**Для справки по исследованной, но исключённой функции:** Responses API подходит для цепочки правок; Images API — для одиночного изменения. Интеграция не планируется. Переменные качества, сохранение мелких деталей/лица/текста и предсказуемость маски надо сравнить на одном наборе изображений и последовательности правок. Использовать закреплённые версии моделей, где доступно; API и модельный каталог меняются. Для GPT Image требуется проверить доступ/верификацию организации.

### Повторно используемый исходник

- Официальный [OpenAI ImageGen demo](https://github.com/openai/openai-imagegen-demo) показывает рабочую интеграцию `/images/edits` в Next.js, выбор моделей, частичные изображения и retry. Это reference implementation, не готовый модуль для Python-продукта.
- Официальный [OpenAI Python SDK](https://github.com/openai/openai-python) включает `client.images.edit`, `client.images.generate` и аудио-транскрибацию. Это основной переиспользуемый интеграционный слой в Python.
- В последовательном редактировании каждый предыдущий image input может влиять на стоимость/контекст следующего шага. Хранение истории и версий остаётся обязанностью приложения.

## 2. Транскрибация встреч

| Вариант | Качество/говорящие | Цена | Задержка | Сложность и условия |
|---|---|---|---|---|
| **OpenAI `gpt-transcribe`** | Текущая рекомендуемая OpenAI модель для готовых записей; русский поддерживается в перечне языков. Можно задавать контекст, ключевые слова и языки. Документированная текущая модель сама по себе не даёт diarized speaker labels | Официальная оценка $0.0045/мин; 10 минут ≈ $0.045 за транскрипцию, без последующего анализа и налогов/прочих услуг | Фиксированный SLA не указан; API поддерживает поток событий по мере готовности | Самый простой hosted путь через официальный SDK. Ограничение: аудиофайл до 25 МБ. Выход и язык на реальной русской записи надо измерить. Новый рекомендованный путь не закрывает требование speaker separation один | 
| **OpenAI `gpt-4o-transcribe-diarize` (только как исследованный, неиспользуемый вариант)** | Возвращает сегменты со speaker, start/end. Сравнивать с реальной записью, особенно при наложении голосов/шуме | В текущем прайсе ориентир для семейства 4o transcribe — около $0.006/мин; отдельно подтвердить актуальную цену именно diarization перед бюджетом | Нет гарантированного времени; файловое потоковое получение возможно | Документация помечает модель deprecated и указывает shutdown **2027-02-26**. Не закладывать как долгосрочное решение. На файлах >30 сек нужна `chunking_strategy=auto` или VAD config |
| **OpenAI `whisper-1` локально** | Открытая модель Whisper, multilingual, MIT. Не выдаёт diarization нативно; нужны отдельные компоненты | Нет платы за минуту после загрузки модели; вычислительные ресурсы и обслуживание оплачиваются владельцем | От секунд до существенно дольше записи в зависимости от модели/GPU/CPU | Нужны PyTorch/модельный вес и обслуживание. Хорошо использовать как fallback/сравнительный baseline; исходный OpenAI Whisper сравнительно тяжёлый |
| **`faster-whisper` + WhisperX + `pyannote.audio`** | `faster-whisper` заявляет до 4× ускорение относительно reference Whisper при той же точности в своих benchmark; WhisperX добавляет word timestamps/alignment и diarization через pyannote. Это не независимое подтверждение точности на нашем русском датасете | Прямого API тарифа нет; цена — GPU/CPU, память, хранение моделей и эксплуатация. На GPU дешевле в масштабе, но нужен GPU-хост | Потенциально быстро на подходящем GPU; на CPU может быть медленно. Проверить на целевой Linux машине | Самый гибкий self-hosted путь, но больше зависимостей и настройки. WhisperX BSD-2-Clause, faster-whisper MIT, pyannote-audio MIT; отдельные pretrained model weights и gated условия Hugging Face проверять по каждой модели. `pyannote.audio` требует принять условия Community pipeline и токен. Нужен контроль конфликтов версий Python/PyTorch/CUDA |

### Рекомендуемый транскрипционный пайплайн для первого прототипа

1. Проверить контейнер/кодек/длительность через FFprobe; не доверять только расширению файла и клиентскому Content-Type.
2. Извлечь аудио через FFmpeg, привести к формату, удобному конкретному ASR. Не сохранять лишние промежуточные копии.
3. В первом этапе принимать видео только до 25 МБ и 10 минут. Извлечённое аудио сжимать до лимита API; если оно всё равно не помещается, выдавать контролируемую ошибку. Чанкинг предусмотреть как путь расширения для будущих больших файлов, но не делать условием MVP без необходимости.
4. Вызвать `gpt-transcribe` для baseline качества и сохранить сырой ответ, язык/параметры и время выполнения. Далее структурировать результат по пяти разделам отдельным текстовым AI-вызовом с требованием не изобретать факты.
5. Метки говорящих отложить. Без них можно выявлять темы, решения и открытые вопросы из содержания расшифровки. Нельзя надёжно распределить задачи между людьми, если ответственный не назван явно: в таких случаях сохранять задачу без ответственного/с пометкой «не определён». Не интегрировать устаревшую OpenAI diarization модель. Возвращаться к оценке устойчивого API или WhisperX + pyannote только если продукту станет важно назначение говорящего.

## 3. Библиотеки, репозитории и строительные блоки

| Строительный блок | Переиспользовать | Зачем | Что проверить |
|---|---|---|---|
| Извлечение аудио/метаданных | [FFmpeg](https://ffmpeg.org/documentation.html) / ffprobe | Читает MP4/WebM, извлекает дорожку и перекодирует для ASR | Установку на Windows и Linux, поддерживаемые codecs, ошибки с повреждёнными файлами; лицензия FFmpeg зависит от build/configuration (LGPL/GPL) |
| API вызовы AI | [OpenAI Python SDK](https://github.com/openai/openai-python) | Официальный клиент для транскрибации и анализа; base URL задаётся конфигурацией `OPENAI_BASE_URL` | Проверить совместимость ProxyAPI с используемыми методами/моделями, retries и rate limits; API-ключи хранить только на сервере |
| ASR/локальный fallback | [faster-whisper](https://github.com/SYSTRAN/faster-whisper), [OpenAI Whisper](https://github.com/openai/whisper) | Локальное распознавание, сравнение провайдеров | GPU/CPU и русский WER, модели отдельно от кода |
| Точность слов/диаризация | [WhisperX](https://github.com/m-bain/whisperX), [pyannote.audio](https://github.com/pyannote/pyannote-audio) | Word-level timestamps, speaker turns | Условия весов, загрузка моделей, ресурсы, совместимость зависимостей и качество при перебиваниях |
| HTTP API | [FastAPI](https://fastapi.tiangolo.com/) | Python API для регистрации, загрузки и просмотра | Не запускать длительную обработку внутри request worker |
| Очередь задач | Celery или другой worker queue | Надёжная повторная/фонова обработка, статусы и ретраи | Для MVP добавить только если нужны устойчивые фоновые задачи; FastAPI docs отдельно указывают, что тяжёлые задачи лучше выносить в Celery/очередь |
| Реляционная БД | PostgreSQL в развернутой среде; SQLite возможен для локального прототипа | Пользователи, приглашения, встречи, job status, agenda/outcome, транскрипт и ссылки на файлы | Схема/миграции, резервное копирование, роли и права. Структурированные секции анализа можно хранить обычными таблицами/полями; JSONB полезен для версионируемого сырого ответа |
| Файловое хранилище | Локальная папка для разработки; S3-compatible объектное хранилище для Linux deployment | Видео и временные аудиофайлы не должны лежать в БД; большие объекты и lifecycle подходят storage | Публичный доступ выключен; выдавать короткие signed URLs либо поток через backend; проверить реальные lifecycle deletion, versioning и backup policy |

Готовые meeting-analyzer репозитории могут служить источниками идей, но не стоит целиком переносить их в проект: они включают ненужные desktop/UI assumptions, модельные лицензии или специфичную GPU-инфраструктуру. Более близкий pipeline пример: [whisper-meeting-transcriber](https://github.com/bennneuh/whisper-meeting-transcriber) (FFmpeg → audio preprocessing → WhisperX → pyannote, resumable steps, MIT); его benchmark claims и совместимость следует независимо воспроизвести.

## 4. Данные: что решить заранее, что может выбрать Codex

Хранение можно и нужно частично определить заранее: утверждённый Product Definition уже фиксирует разные сроки — видео и временное аудио 24 часа по умолчанию, транскрипт/результаты до удаления. Это продуктовые требования, и они не должны оставаться на усмотрение инструмента реализации.

Технология хранения — предварительное инженерное решение, которое Codex может предложить и реализовать в рамках среды: локальная файловая система при разработке, PostgreSQL для сущностей и объектное/S3-compatible хранилище для крупных файлов на сервере. Конкретный провайдер, регион, стоимость, резервирование и администраторские механизмы удаления зависят от выбранного хостинга — их требуется выбрать до публичного развёртывания.

Рекомендуемая схема данных:

- **PostgreSQL:** users, invitations, meetings, processing jobs/status, agenda/outcome/next meeting, structured result, transcript (текст + JSON segments), timestamps, storage keys, retention/deletion timestamps.
- **Object storage:** исходное видео и временный извлечённый аудиофайл в отдельных приватных bucket/prefix. Не помещать binary blobs в таблицы.
- В базе хранить storage key, MIME/codec, размер, длительность, checksum и фактический `expires_at`, но не публичный URL.
- Чистка должна быть двуслойной: lifecycle policy хранилища плюс периодическая задача приложения и reconciliation для ошибок. Проверить поведение object versions: удаление текущей версии может оставить предыдущие версии.
- Не включать исходное видео/аудио в логи. Ограничить сроки API-провайдера отдельно от локального retention: OpenAI API данные не используются для обучения без явного согласия, но abuse-monitoring и application-state retention регулируются отдельно. Проверить эти условия и настройки перед обработкой пользовательских записей.

Следовательно, **сроки, категории данных, кто имеет доступ и поведение удаления определяются продуктом заранее; точный storage vendor и развёртывание Codex может предложить после выбора целевого Linux-хостинга**. Codex не должен молча выбирать регион/провайдера или менять утверждённую политику хранения.

## 5. Вопросы, требующие практической проверки

1. Русская точность `gpt-transcribe` на реальной встрече: имена, термины, акценты, шум, перебивания и качество микрофона.
2. Достаточность обычной расшифровки для пяти выводов; фактическая точность задач и решений без меток говорящих. Не назначать ответственного при отсутствии явного подтверждения.
3. Приём исходных файлов до 25 МБ и 10 минут; извлечение/сжатие аудио в предел 25 МБ для ASR.
4. Полное время обработки, отказы, таймауты и понятные статусы на целевой Linux-конфигурации REG.RU.
5. Повторная обработка после сбоя без дубликатов, удаление временных материалов через 24 часа и удаление результата администратором.
6. Архитектурная готовность к будущим большим файлам: потоковая загрузка, чанкинг аудио, продолжение/повтор частей и контроль временного дискового пространства. Большой размер не включать в первую версию.
7. Вывод AI по пяти разделам: фактическая опора на транскрипт, доля выдуманных решений/задач, корректная формулировка «не обнаружено/неясно».
8. Отдельно подтвердить в Timeweb Cloud выбранную конфигурацию, доступность managed PostgreSQL и объектного хранилища либо выбрать управляемые альтернативы.

## Дополнительное интервью и зафиксированные ответы

1. **Редактирование изображений не входит в продукт.** Это исследование не создаёт требования на интеграцию. Администратор может менять текстовые выводы встречи.
2. **Метки говорящих желательны, но отложены для первой версии.** Выводы по содержанию встречи можно строить по обычной расшифровке. Без speaker labels модель не может надёжно привязать высказывания к участникам; ответственного указывать только если он явно назван в разговоре, иначе оставлять неизвестным.
3. **Выбрано облачное API** для распознавания; начальная конфигурация — `OPENAI_BASE_URL=https://api.openai.com/v1`, с возможностью переключения на `OPENAI_BASE_URL=https://api.proxyapi.ru/v1`. Устаревшие модели использовать не планируется.
4. **Timeweb Cloud выбран как целевая площадка** для Linux-размещения. Конкретный продукт/тариф и конфигурацию предстоит выбрать при подготовке развертывания.
5. **Изменения выполняет только администратор.** Студенты и проверяющие только просматривают; удаление сохранённых результатов тоже администраторское.
6. **Передача записей внешнему AI-сервису разрешена.** Условия хранения данных у провайдера и локальный срок удаления всё равно учитывать в реализации.
7. **Лимит первого этапа — 25 МБ и 10 минут на видео.** Поддержка больших файлов — направление будущего расширения; для неё предусмотреть потоковую загрузку и chunking.

### Можно ли сделать выводы без меток говорящих?

Да. Краткое содержание, темы, решения, открытые вопросы и сами формулировки задач можно извлекать по тексту и контексту разговора без diarization. Теряется надёжная атрибуция: кто предложил решение, взял задачу или отвечает за неё. Если человек назван явно, это можно отразить; иначе ответственного следует оставить пустым или обозначить как «не определён». Для снижения выдумок выводы следует хранить вместе с подтверждающими фрагментами расшифровки и показывать неопределённость. Структурированный формат API гарантирует форму JSON по схеме, но не фактическую точность содержимого, поэтому качество нужно проверить на реальных записях.

См. [рекомендуемый `gpt-transcribe`](https://developers.openai.com/api/docs/guides/speech-to-text) и [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).
