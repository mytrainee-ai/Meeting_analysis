# Meeting Analysis

Веб-сервис анализа записей встреч. Требования к продукту описаны в [PRD](docs/03-prd.md).

## Локальный запуск

Требуется Python 3.12.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Откройте `http://127.0.0.1:8000/` для загрузки MP4 и WebM. Проверка сервера: `http://127.0.0.1:8000/health`.

При первом открытии локальное приложение предложит создать администратора. Это действие доступно только через loopback (`127.0.0.1`/`::1`); задайте адрес почты и пароль длиной не менее 8 символов. Секрет подписи сессий автоматически создаётся в локальном `.env`, если `APP_SECRET_KEY` пуст. Сессия действует 12 часов. Администратор выдаёт многоразовые коды приглашений на странице «Приглашения и доступ»; регистрацию без кода сервер отклоняет.

Для серверной проверки загружаемых видео нужны `ffprobe` и `ffmpeg` из FFmpeg, доступные через `PATH`. Загруженные файлы и SQLite-метаданные находятся в `data/`; каталог исключён из Git. Путь можно изменить переменной `MEETING_DATA_DIR`.

Текущий прототип принимает MP4 и WebM до 25 МБ и 10 минут. На странице загрузки можно отменить передачу и вернуться к списку встреч. На странице встречи можно явно запустить облачную обработку: извлечение аудио, русскую транскрибацию и формирование итогов. Для этого задайте `OPENAI_API_KEY` в локальном `.env`; обработка может расходовать средства по тарифу API. Результаты и статус хранятся в SQLite, временное аудио удаляется после запроса, исходное видео очищается через 24 часа при старте или следующем успешном просмотре списка/встречи. Используйте локально; для размещения потребуется HTTPS (`COOKIE_SECURE=true`), эксплуатационная конфигурация и дополнительная проверка.

## Структура

- `app/` — серверное приложение.
- `docs/` — описание продукта, техническое исследование и PRD.

Локальный прототип поддерживает загрузку и обработку MP4/WebM с серверной проверкой владельца встречи.
