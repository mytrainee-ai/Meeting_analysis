# Meeting Analysis

Веб-сервис для обработки записей встреч: загружает MP4/WebM, получает расшифровку фактической речи и формирует краткое содержание, темы, решения, задачи и открытые вопросы. Демонстрационные данные не подменяют пользовательские записи.

Текущие продуктовые требования — в [PRD](docs/03-prd.md), принятые решения — в [DECISIONS.md](docs/DECISIONS.md), состояние проекта — в [CURRENT_STATE.md](docs/CURRENT_STATE.md).

## Возможности

- Регистрация только по активному приглашению; аккаунты обычных пользователей и администратора.
- Пользователь видит, редактирует и удаляет только свои встречи; администратор видит все встречи и управляет доступом.
- Загрузка MP4/WebM до 25 МБ и 10 минут с проверкой содержимого, прогрессом передачи, вращающимся индикатором ожидания и отменой.
- Автоматическая обработка после согласия на облачную передачу и возможные расходы; повтор после сбоя запускается явно.
- Просмотр статуса и диагностики ошибки, ручная правка встречи и результатов.
- Массовое удаление встреч текущего пользователя. Учётные записи и приглашения при этом не меняются.
- Видео и временное аудио удаляются по сроку хранения; текстовые результаты остаются до удаления встречи.

## Локальный запуск

Требуются Python 3.12, FFmpeg и FFprobe.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните `.env`: задайте `OPENAI_API_KEY`, оставьте `OPENAI_BASE_URL=https://api.openai.com/v1` либо укажите поддерживаемый endpoint. Не добавляйте `.env` в Git и не присылайте его содержимое.

Запустите приложение:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Откройте <http://127.0.0.1:8000/>. При первом запуске база создаётся автоматически; начальная настройка администратора доступна только с loopback. `/health` проверяет доступность процесса.

Сессия входа — cookie браузерной сессии; перезапуск процесса приложения отзывает активные входы. Аккаунты, встречи и результаты в SQLite от этого не удаляются.

Файлы и база хранятся в `data/`; корневой каталог можно изменить через `MEETING_DATA_DIR`. В `.env` хранятся локальные секреты. В Git добавляется только `.env.example` без секретов.

## Серверный пилот

Пилот опубликован на [app.traineeserver.ru](https://app.traineeserver.ru). Автоматическое обновление настроено через GitHub Actions при push в `main`; deployment включён repository variable `PILOT_DEPLOY_ENABLED=true`. Выпуск релиза перезапускает `meeting-analysis.service`.

Пилот использует одну VM, один Uvicorn worker, SQLite и локальный диск. Обработка выполняется фоновыми задачами внутри процесса: перезапуск во время обработки может прервать задачу, после чего её нужно повторить вручную. Резервное копирование пока отложено решением владельца. Подробности и эксплуатационные ограничения — в [DEPLOYMENT.md](docs/DEPLOYMENT.md).
