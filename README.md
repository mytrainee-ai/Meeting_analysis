# Meeting Analysis

Веб-сервис анализа записей встреч. Требования к продукту описаны в [PRD](docs/03-prd.md).

## Локальный запуск

Требуется Python 3.12.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

Откройте `http://127.0.0.1:8000/` для загрузки MP4 и WebM. Проверка сервера: `http://127.0.0.1:8000/health`.

При первом открытии локальное приложение предложит создать администратора. Это действие доступно только через loopback (`127.0.0.1`/`::1`); задайте адрес почты и пароль длиной не менее 8 символов. Секрет подписи сессий автоматически создаётся в локальном `.env`, если `APP_SECRET_KEY` пуст. Сессия действует 12 часов. Администратор выдаёт многоразовые коды приглашений на странице «Приглашения и доступ»; регистрацию без кода сервер отклоняет.

Для серверной проверки загружаемых видео нужны `ffprobe` и `ffmpeg` из FFmpeg, доступные через `PATH`. Загруженные файлы и SQLite-метаданные находятся в `data/`; каталог исключён из Git. Путь можно изменить переменной `MEETING_DATA_DIR`.

Текущий прототип принимает MP4 и WebM до 25 МБ и 10 минут. Выберите файл и подтвердите согласие на автоматическую передачу аудио и расшифровки в облачный AI-сервис и возможные расходы: передача начнётся сразу, отдельной кнопки загрузки нет. После успешной загрузки обработка запускается автоматически, а приложение возвращает к списку встреч с индикацией этапа. Загрузку можно отменить. Для обработки задайте `OPENAI_API_KEY` в локальном `.env`. Результаты и статус хранятся в SQLite, временное аудио удаляется после запроса, исходное видео очищается через 24 часа при старте или следующем успешном просмотре списка/встречи. Используйте локально; для размещения потребуется HTTPS (`COOKIE_SECURE=true`), эксплуатационная конфигурация и дополнительная проверка.

## Структура

- `app/` — серверное приложение.
- `docs/` — описание продукта, техническое исследование и PRD.

## Публикация на сервер

Публичный запуск ещё не выполнен. Ограниченная схема пилота и автоматического обновления описана в [плане публикации](docs/DEPLOYMENT.md): HTTPS, безопасный deploy-доступ, резервное копирование и настройка GitHub Actions остаются обязательными шагами.

После первичной настройки пилотного сервера предполагается автоматический deploy при push в `main` через GitHub Actions. Настройки workflow и ограничения описаны в [плане публикации](docs/DEPLOYMENT.md); автоматизация остаётся выключенной до подготовки SSH-доступа и проверки первого deploy.

Локальный прототип поддерживает загрузку и обработку MP4/WebM с серверной проверкой владельца встречи.
